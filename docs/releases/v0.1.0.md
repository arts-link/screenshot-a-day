# Screenshot-a-Day v0.1.0

Screenshot-a-Day is a self-hosted visual history for websites. This initial release schedules reproducible Chromium, Firefox, and WebKit captures, compares changes, publishes galleries and GIF/WebM timelines, and sends signed webhooks.

## Highlights

- Self-hosted API, browser worker, administrator UI, and public galleries.
- Encrypted target headers and cookies, private-network protection, and explicit sharing modes.
- Cross-browser capture profiles, schedules, retention, side-by-side comparison, overlays, and heatmaps.
- Docker Compose deployment with a single persistent data volume.
- REST API, OpenAPI documentation, and signed outbound webhooks.

## Install

The release is distributed only through GitHub Container Registry:

```text
ghcr.io/arts-link/screenshot-a-day-api:0.1.0
ghcr.io/arts-link/screenshot-a-day-worker:0.1.0
```

Clone the `v0.1.0` source, generate the three secrets described in `.env.example`, and start the pinned images:

```sh
git clone --branch v0.1.0 https://github.com/arts-link/screenshot-a-day.git
cd screenshot-a-day
cp .env.example .env
# Set SAD_ENCRYPTION_KEY, SAD_SESSION_SECRET, and SAD_WORKER_TOKEN.
docker compose pull
docker compose up -d
docker compose logs api
```

Continue at `/setup` with the one-time token from the API log. Read the [deployment guide](../guides/deployment.md) before exposing the service publicly.

## Supply-chain verification

The release workflow publishes linux/amd64 and linux/arm64 images. GitHub provenance attestations and SBOM attestations are attached to each immutable image digest. The generated GitHub Release body records those digests.

With the GitHub CLI, verify an image against this repository:

```sh
gh attestation verify oci://ghcr.io/arts-link/screenshot-a-day-api:0.1.0 --repo arts-link/screenshot-a-day
gh attestation verify oci://ghcr.io/arts-link/screenshot-a-day-worker:0.1.0 --repo arts-link/screenshot-a-day
```

## Supported platforms and limitations

The supplied images support Docker-compatible linux/amd64 and linux/arm64 hosts. Docker Desktop can run them on supported macOS and Windows hosts through its Linux VM.

This is a pre-1.0 release. Database migrations are forward-only, horizontal API scaling is not supported with the default SQLite storage, and operators are responsible for storage, TLS, backups, monitoring, retention, and target authorization. Screenshot-a-Day includes no product telemetry. Captures are not signed, certified, or tamper-proof; only outbound webhooks are cryptographically signed.
