# Screenshot-a-Day v0.1.1

Screenshot-a-Day v0.1.1 is a focused reliability and security patch for self-hosted v0.1.0 installations. It hardens administrator recovery and keeps sensitive one-time values and form feedback beside the controls that produced them.

## Highlights

- Administrator recovery is atomic: the one-time recovery token is consumed with the password update and all administrator sessions are revoked in the same transaction.
- Browser clients whose sessions expire or are revoked return to the explicit Login route with actionable messaging.
- Logout never falls back to the completed setup experience, including during reload and back/forward navigation.
- Capture-profile and webhook-creation forms expose local pending, success, validation, and network states without discarding failed input.
- API tokens and webhook signing secrets provide adjacent copy confirmation plus a full-value selection fallback when clipboard access is unavailable.
- Publication destination dialogs protect unsaved changes from accidental backdrop, Escape, and cancel dismissal.
- Capture cards show sharp top-of-page previews instead of stretched full-page thumbnails. Existing preview artifacts rebuild automatically from retained originals after upgrade; full screenshots remain unchanged.
- The project website self-hosts its fonts.

## Upgrade from v0.1.0

No database migration is included in this release, but data migrations are forward-only in general. Take a consistent backup before upgrading:

```sh
docker compose stop worker api
docker compose cp api:/data ./screenshot-a-day-backup-v0.1.0
docker compose start api worker
```

Update the checkout to the annotated `v0.1.1` tag, retain the existing `.env` and `sad-data` volume, then pull and recreate the services:

```sh
git fetch --tags origin
git checkout v0.1.1
docker compose pull
docker compose up -d
docker compose ps
curl -fsS http://localhost:4400/version
docker compose logs --tail=100 api worker
```

Do not use `docker compose down -v`; removing the volume deletes the default SQLite database and captured artifacts.

After startup, the API repairs existing preview artifacts in the background and marks attached static galleries for republishing. This may briefly increase CPU and disk activity on installations with long capture histories. Full-resolution originals are read but never modified.

## Security

Password recovery now invalidates all existing administrator sessions. This is intentional: after a successful recovery, sign in again with the new password on every browser or API client.

Do not report vulnerabilities in a public issue. Use the repository's private vulnerability reporting flow described in the [security policy](../../SECURITY.md).
